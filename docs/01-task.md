# 01. Постановка задачи

## Кейс
**«Полка под контролем: создайте решение для Lenta Tech»** — Lenta Tech Life Hack (2026).

Lenta Tech — IT-бренд «Группы Лента» (>6 тыс. магазинов). В сети уже работает видеоаналитика со стационарных камер; следующий шаг — мобильные камеры на роботе, который объезжает стеллажи. Наш кейс — превратить этот видеопоток в структурированные данные о ценниках.

## Что нужно сделать

1. **Предобработка видео** с робота (видео ~1080p–4K, разные сцены: алкоголь, молочка, мёд, джемы, сиропы).
2. **Пайплайн** детекции и распознавания ценников. На каждый уникальный ценник в видео — одна строка CSV из **30 полей** (см. ниже).
3. **UI**: загрузка видео → скачивание CSV.
4. **Презентация** (титул, команда, анализ, архитектура, демо, ограничения, ссылки на репо и деплой).

## Поля выходного CSV

### 18 полей с самого ценника

| Поле | Описание |
|---|---|
| `filename` | имя видеофайла |
| `product_name` | наименование товара |
| `price_default` | цена без карты |
| `price_card` | цена по карте |
| `price_discount` | цена по акции |
| `barcode` | штрихкод |
| `discount_amount` | размер скидки (например, «-23%») |
| `id_sku` | артикул |
| `print_datetime` | дата и время печати ценника |
| `code` | код зоны выкладки |
| `additional_info` | доп. информация |
| `color` | цвет ценника (red/yellow/green/white) |
| `special_symbols` | тип выкладки (Ш/К/Л) |
| `frame_timestamp` | мс от начала видео |
| `x_min`, `y_min`, `x_max`, `y_max` | bbox в пикселях |

### 12 полей из QR-кода

| Поле | Поле в QR |
|---|---|
| `qr_code_barcode` | `barcode` / `b` |
| `price1_qr` | `price1` / `p1` |
| `price2_qr` | `price2` / `p2` |
| `price3_qr` | `price3` / `p3` |
| `price4_qr` | `price4` / `p4` |
| `wholesale_level_1_count` | `wholesaleLevel1Count` / `wL1C` |
| `wholesale_level_1_price` | `wholesaleLevel1Price` / `wL1P` |
| `wholesale_level_2_count` | `wholesaleLevel2Count` / `wL2C` |
| `wholesale_level_2_price` | `wholesaleLevel2Price` / `wL2P` |
| `action_price_qr` | `actionPrice` / `aP` |
| `action_code_qr` | `actionCode` / `aC` |

**Соглашение по пропускам:**
- Поле физически отсутствует на ценнике → `нет`.
- Поле не удалось распознать → пусто.

## Критерии успеха (из ТЗ)

| # | Критерий |
|---|---|
| 1 | Доля ценников, у которых распознано ≥80 % полей → **главная метрика** |
| 2 | Структурированный CSV (формат соблюдён) |
| 3 | Публичный задеплоенный UI (бонус) |
| 4 | Локально-разворачиваемое, без облачных API |
| 5 | Масштабируемость; работа на слабом железе — бонус |

## Ограничения

- Только локально-разворачиваемые модели/библиотеки. **Никаких облачных API.**
- Ручная разметка запрещена. Автоматические методы (включая использование GT-CSV от организаторов как обучающую разметку) — разрешены.
- Лёгкая модель. RKNN/int8 — приветствуется.
