# 05. Главная гипотеза и план экспериментов

## H0 (главная гипотеза)

> **QR-код на ценнике Ленты содержит 7–8 полей напрямую, и его декодирование даёт ~100 % точности на этих полях. Если мы:**
>
> 1. надёжно детектируем ценник на видео и треком связываем повторные появления (один ценник = одна строка CSV);
> 2. декодируем QR в лучшем кадре трека → получаем `barcode`, `price1..4_qr`, оптовые уровни, акционные поля;
> 3. определяем цвет ценника по HSV → `color`;
> 4. классифицируем шаблон ценника (7 базовых, см. `03-templates.md`) → для каждого знаем ROI каждого текстового поля;
> 5. запускаем PaddleOCR (ru) только по нужным ROI и парсим строки regex-правилами;
>
> **то мы достигнем ≥80 % правильно распознанных полей на ≥70 % ценников в контрольном видео.**

### Почему это рабочая ставка
- QR декодируется в библиотеках за 0.5–1.5 мс и даёт **8 точных полей** (~27 % от 30 колонок), на которые иначе пришлось бы тратить OCR.
- Шаблонов всего 7, и они **жёстко фиксированы** — это превращает «свободный OCR» в задачу заполнения формы.
- Tracker экономит OCR: один ценник OCR-им 1 раз (по best-frame), а не N раз.
- Все компоненты — легковесные, помещаются на CPU; YOLO + ByteTrack + PaddleOCR-mobile реально работают real-time на CPU.

## Альтернативные гипотезы (если H0 рушится)

| ID | Гипотеза | Когда тестируем |
|---|---|---|
| H1 | QR не везде читается (блики, низкое разрешение) → нужен super-resolution (ESRGAN-tiny / Real-ESRGAN-x2 nano) перед декодером | если в Д3 QR-success < 70 % |
| H2 | PaddleOCR теряет точность на цифрах под углом → попробовать **TrOCR** или специализированный число-OCR | если Д4 показывает большой провал именно на ценах |
| H3 | YOLO-nano недотягивает по recall (теряет частично скрытые ценники) → апгрейд до YOLO-s или fine-tune с более длинной разметкой | если Д3 recall < 0.85 |
| H4 | Template-классификатор ошибается → fallback на «универсальный парсер» без ROI | подстраховка с Д3 |
| H5 | Дедупликация по track_id не схлопывает все повторные появления (робот возвращается) → добавить **дубль-фильтр по barcode** | Д4 |

## План экспериментов

| Эксп. | Что меряем | Бейзлайн | Цель |
|---|---|---|---|
| **E1: детектор** | mAP@0.5, recall на val (`43_15`) | YOLO pretrained — recall ~0.6 | recall ≥ 0.9 после fine-tune |
| **E2: QR success rate** | доля ценников с успешным декодом QR | — | ≥ 90 % |
| **E3: OCR — цена** | exact match по цене (`price_default`, `price_card`) | PaddleOCR raw — ~75 % | ≥ 95 % |
| **E4: OCR — текст** | fuzzy match по `product_name` | PaddleOCR raw — ~80 % | ≥ 90 % |
| **E5: tracker** | precision дедупликации (1 уник = 1 трек) | ByteTrack default | ≥ 95 % |
| **E6: end-to-end** | главная метрика (доля ценников с ≥80 % полей) | — | ≥ 70 % |

Все эксперименты — в `notebooks/` и логируются в `outputs/exp/`.

## Что считаем успехом / провалом

- **Зелёная зона:** E6 ≥ 70 % на 43_15 → можно полировать UI и презу.
- **Жёлтая:** E6 = 50–69 % → переключаемся на H2/H3 (тяжелее OCR / детектор).
- **Красная:** E6 < 50 % → пересматриваем стратегию (возможно, отказ от шаблонного парсинга в пользу LLM-OCR, но это последняя миля).
