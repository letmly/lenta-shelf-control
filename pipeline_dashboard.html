🔬 Этапы pipeline

1. RAW frame (вход)

Вход: mp4 видео 3840×2160, ~20 fps, h264, fisheye

Выход: кадр-numpy (2160, 3840, 3) в BGR

Алгоритм: cv2.VideoCapture.read()

Параметры камеры от орга (14.05 18:37):
• 3840×2160
• Объектив 16/2.8mm (1/2.8" матрица, focal 2.8mm)
• Видео повёрнуто на 90° против часовой стрелки!
• Дисторсия: подбирать самим

2. Rotation CCW (фикс ориентации) — NEW в v8!

Вход: кадр (2160, 3840, 3)

Выход: кадр (3840, 2160, 3) в правильной ориентации

Алгоритм: cv2.rotate(frame, cv2.ROTATE_90_COUNTERCLOCKWISE)

Почему: текст и ценники теперь горизонтально → OCR работает.

Примечание: делаем поворот ТОЛЬКО на crop'е перед OCR, координаты bbox остаются в исходной системе (как в GT).

3. Multicolor detection

Вход: кадр

Выход: список (bbox, color) — найдено 24 на этом кадре

Алгоритм: HSV маски red/yellow/green → морфология (close+open) → connected components → bbox

Параметры: min_area=4000 px², aspect 0.25..4, global NMS IoU≥0.3

Recall на 26_12-20 GT: ~60% (red-only был 60%, multicolor шумит)

4. Tracker (IoU-based)

Вход: на каждом 6-м кадре — список bbox-detections

Выход: треки (один track_id = один ценник через несколько кадров)

Алгоритм: для каждого dets ищем active track с max IoU ≥ 0.25, иначе создаём новый

Параметры: IoU threshold 0.25, max_missed_ms 600, min_track_frames 3

Проблема: 3× over-detection (848 pred vs 274 GT). Treker связывает шумные bbox в треки.

5. Best-frame per track

Вход: трек с N кадрами

Выход: один best_crop (max sharpness)

Алгоритм: cv2.Laplacian(gray, cv2.CV_64F).var()

Memory fix: храним только best_crop в треке, не все кадры. RAM ×50 ниже.

6. Crop rotation + upscale (готовим к OCR) — NEW в v8!

Вход: best_crop (исходная ориентация)

Выход: rotated CCW + upscale ×3 → готов для OCR

Алгоритм: cv2.rotate(crop, CCW) → cv2.resize(fx=3, fy=3, INTER_CUBIC)

Зачем upscale: OCR пасует на crop'ах меньше 200×300 px. Upscale x3 = 600×900 → OCR работает.

7. RapidOCR

Вход: rotated upscaled crop

Выход: список (bbox, text, confidence) entries

Алгоритм: DBNet++ детекция текста + CRNN/SVTR распознавание (русский + латиница)

Лицензия: Apache 2.0, ONNX-runtime, CPU-friendly

Параметры: use_angle_cls=True (поворачивает буквенные строки если они под углом)

Замечание: рассматриваем замену на PP-OCRv5 East-Slavic — 81.6% line-exact на русском (vs ~70% у обычного RapidOCR).

8. Parser OCR → CSV fields

Вход: OCR entries

Выход: dict с 23 распознаваемыми полями

Алгоритм:

  • discount_amount: regex -?(\d{1,2})\s*%
  • print_datetime: regex \d{2}\.\d{2}\.\d{4} + время
  • price_card: самая высокая ^\d{2,4}$ строка + поиск 2-цифр копеек рядом
  • price_default: вторая по высоте (50-95% от price_card)
  • barcode: ^\d{8,14}$ + склейка соседних цифровых сегментов
  • id_sku: ^\d{10,12}$
  • product_name: все строки с буквами (фильтр >= 2 букв)
  • color: от детектора (red/yellow/green)

Проблема: парсер слабый, 0% на product_name/prices/barcode на матченных строках. Дефолт «нет» для 7 always-нет полей даёт mean=33% на GT-bbox (диагностика).

9. CSV writer

Вход: словари полей, один на track_id

Выход: CSV в формате sample.csv (29 колонок, точка = десятичный разделитель)

Дефолт для 7 always-нет полей: "нет" (price_discount, wholesale_*_count/price, action_*_qr)

10. Evaluate (метрика согласно ТЗ + чату орга 14.05)

Вход: pred CSV + GT CSV

Алгоритм:

  1. Матчинг строк: barcode primary (если совпали), иначе spatial-temporal (|Δts|≤1500ms, IoU≥0.3)
  2. Для матченной пары — % содержательных полей совпало (24 поля, технические не учитываются)
  3. Зачёт: ≥80% полей правильно
  4. Итоговая метрика: доля зачтённых ценников от |GT|
