🎯 Гипотезы и результаты

QR/штрихкод декодирование

❌ ЗАКРЫТО

20+ комбинаций (pyzbar, zxing-cpp, PyBoof, WeChat, QReader) × 100 ценников × multi-frame fusion × lucky imaging × perspective rectify × Real-ESRGAN x4 = 0/100 матчей с GT-штрихкодом. Sanity-check на синтетике: декодеры работают только от 80px QR, у нас 48px → физический предел. Сильный аргумент в питче.

Red-mask детектор для красных ценников

✅ Работает

Простой cv2.inRange по HSV красного + connected components → ~60% recall на размеченных видео. Не требует обучения, детерминирован.

Multicolor detector (red/yellow/green)

🟡 Частично

В видео 49_5 есть жёлтые ценники → multicolor нужен. Но даёт много false positive на жёлтых этикетках/зелёных упаковках товаров. Нужна доводка.

Multi-frame stacking / Lucky imaging

❌ Не помогло для QR

Median по 30+ выровненным кадрам + Lucky imaging top-K sharpest + ECC alignment → визуально картинка чище, но декодеры всё равно не справляются.

RapidOCR (Apache 2.0) для текста

✅ Работает

На правильных crops с padding +25% и upscale ×3 — читает русский+латиницу. Видели 'UOULNDELA' = MOULIN DE LA. На кропах от нашего детектора (с extension вниз) — пасует, только обрывки 'ca', 'mm'.

Дефолт 'нет' для 7 always-нет полей

✅ ОГРОМНЫЙ win

В GT для 7 полей (price_discount, wholesale_*_count/price, action_*_qr) — всегда 'нет' (для красных ценников). Если по умолчанию писать 'нет' → +28 п.п. mean score без касания OCR.

🔍 Визуальные примеры

Один и тот же ценник, разные crops → разный OCR:

GT bbox с padding +25%, upscale x3 (правильно):
OCR: ['302345', 'oo', 'FArE Une Wyey', 'UOULNDELA']
→ читается "MOULIN DE LA"!
Bbox от нашего detector v5 (плохо):
OCR: ['I']
→ один обрывок!

Это значит: OCR работает на правильных crops, проблема — наш детектор даёт неоптимальные bbox.
